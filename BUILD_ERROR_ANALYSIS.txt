EXECUTIVE SUMMARY
================================================================================

Root Cause:
-----------
Two incompatible definitions of "MemberStatus" exist in the codebase with
identical names but different type systems:

1. Domain Layer (Enum):    src/core/utils/constants/StatusConfig.ts
   Type: enum MemberStatus { Active = 'active', ... }

2. Schema Layer (Zod):     src/features/members/schemas/member.schemas.ts
   Type: z.enum(['active', 'expired', ...]) → "active" | "expired" | ...

The API route validates requests using Zod (returns string literals), then
passes the data to a repository that expects TypeScript enum types. TypeScript
rejects this mismatch during production builds.

Impact:
-------
- Production deployment BLOCKED on Vercel
- Type safety broken between validation and domain layers
- State machine transitions at risk of type system bypass

Solution:
---------
Replace Zod string literal enum with z.nativeEnum(MemberStatus) to use the
domain layer's enum definition as single source of truth.

Estimated Fix Time: 30-60 minutes

# Member writes — Inverted Check (2026-11-04)

> **Premise.** The member-write fixes on `verify/member-write-races` (030148b … 8c833b9) shipped green: type-check, lint, `arch:check`, the full suite, 30+ mutation checks, a local race harness and rendered screenshots. Every one of those checks was built by the same author from the same assumptions. This check assumes each claim is wrong and attacks it with a different instrument:
>
> - **PostgREST 14.5**, the version production runs (read from its OpenAPI `info.version`), instead of the 13.0.8 the harness first used;
> - **UTC**, the time zone Vercel runs in, as well as the machine's +05:30;
> - the **real route handlers** with the real `payments` and `sms_logs` tables, rows counted in the database instead of in stubs;
> - **rolled-back transactions on production**, as the E2E gym's owner;
> - a **real browser** through the app's own member-modal provider;
> - an **exact pixel diff** against the committed 1366 baseline.
>
> Grades follow `workspace-ui-inverted-check.md`: **BUG**, **DEBT**, **HOLE**, **WRONG**.

## Clean (the probe could have failed and did not)

- **The race harness on production's PostgREST (14.5)**, in +05:30 and in UTC: 39 of 39 checks, including the READ COMMITTED re-check (a guarded write blocked on another transaction writes 0 rows when that one commits and applies when it rolls back).
- **The real routes, rows counted in the database.**
  - Two Mark Paid requests released together: 201 and 409, one `payments` row and one receipt in `sms_logs`.
  - Two day passes: one `day_pass` row.
  - A day pass at a Lite gym's 100th member: 403, no payment and no SMS, member still expired.
  - Suspend while the cron's status change commits: 409, the member stays expired.
  - Cancel released behind a payment: payment 201, cancel 409, the member active.
  - A plan-switching reactivation after a plan edit: 409, no payment, the edit kept. On its own: 201, plan switched, one reactivation SMS.
- **The phone save on production, rolled back**: own row 1; Titan Fitness's number raised 23505 (the route's 409); another gym's row 0; a non-canonical number raised 23514. Nothing persisted.
- **Consent survives a rename** (what the handoff wanted from `access-control-member.spec.ts`, which was not run: it sends an enrol command to a physical reader). Through the real `PATCH /api/members/[id]`, with a consent recorded in a transaction that commits while the rename waits on the row, the consent survives. The old whole-row write, put back as a mutant, reverts it to null.
- **The member screen after a refused suspend or activate** (real browser, the app's `MemberModalProvider`, fetch stubbed with a server whose copy changes underneath): the member is fetched again (1 call to 2) and the screen shows the server's status and due date, at 1366 and 390.
- **The 16 px description gap** measured in Mark Paid, Add Member, Bulk Add and Discounts at 1366 and 390, and on the live Member Details.
- **The plan guard** compares the raw `plan_type`, so a gym's custom plan types do not raise false conflicts. A 3333.50 plan matches its own guard through PostgREST's numeric comparison.
- **The due-date guard** compares UTC-parsed dates, so it does not depend on the server's time zone.
- **Only the three routes** call the guarded suspend, cancel and reactivate use cases.
- **"Change your phone number … again"** in d7cb490's Release-Note is true: the OTP routes existed until fc4612f.
- **`mobile-probe` on `/settings/security`**, phone-390 and desktop-1366: clean.

## What this says about the method

- **A tolerance is a blind spot with a number on it.** The regression spec passed a 16 px move because it was built to absorb date drift; only an exact diff could show what moved and what did not.
- **A mutant must be the old defect, not a neighbour of it.** The first consent mutant ("write every writable field") passed, because consent was never a writable field. Only the literal old behaviour (write the whole row) failed the test. A mutant that does not reproduce the defect proves nothing about the test.
- **Two of my own instruments overwrote their evidence.** A mutation run wrote its 500 body over the passing 403 body (observation 0018), and a later Playwright run cleared `test-results/` before the diff images were read. Both were caught before they became findings, and outputs were then written to paths keyed by the run.
- **A shared limit is spent by every probe.** One regression run, one capture and one re-run left nothing for the probe (observation 0015, third time). The fix is structural (D2), not care.

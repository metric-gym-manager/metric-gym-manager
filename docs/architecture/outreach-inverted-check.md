# Outreach series: inverted check

A falsifying check of the four-email outreach series, focused on unsubscribing and on the automated sends (2026-10-06, after the 82-business list was imported and before any email reached it). Every finding was reproduced or measured first, fixed test first, then mutated back to the defect to show the test catches it (M1–M6, plus O8's test). The design is in `marketing-email.md`, "Outreach".

## Checked, and holding (live, on production)

- **The footer link.** A prospect's /unsubscribe page answers 200, shows the Marketing choice and the address, and is `noindex`. **Opening it changes nothing**: the address read as still subscribed afterwards.
- **One-click from a mail app.** The exact RFC 8058 request answered 200, and Resend read Marketing `opt_out`. A forged token got 400. A GET (a person opening the URL) is sent to /unsubscribe with 303.
- **After an unsubscribe** the next week's run skipped the address and marked it `unsubscribed`, while the others got email 2.
- **Resend's log** carries `kind=outreach`, `campaign` and `email` = 1 to 4 on every send.
- **The list:** 82 rows, 82 distinct addresses, all `active` at step 0, each with its website as the source. 82 Resend contacts were added, each with a token, in no segment.
- **No address can get the same email twice:** the step is claimed in the database, Resend gets an idempotency key per address and step, and the six-day gap applies.

## Known and accepted

- **A reply saying "unsubscribe"** (the `mailto` fallback in the header) arrives in the hello@ inbox. Someone has to act on it: `npx tsx scripts/send-outreach.ts --remove their@email`.
- **Spam complaints and hard bounces** are suppressed by Resend itself, which will not deliver to that address again. The ledger does not record them, so they may still count as `sent`.
- **Opening /unsubscribe shows two checkboxes,** including "Product and security updates", which a prospect never receives. It is harmless, since Marketing comes pre-ticked from the link.
- **`--run` by hand does not wait for the start date.** It is a deliberate manual override.

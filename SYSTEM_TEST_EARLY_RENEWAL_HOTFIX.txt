❌ GAP 3: Missing Error Edge Case Validation
====================================================
Severity: MEDIUM

Issue: The renew() method validates status but doesn't validate the newDueDate parameter

Current Implementation Problem:
-------------------------------
renew(newDueDate: Date): Member {
  if (this.props.status !== MemberStatus.Active) {
    throw new InvalidStatusTransitionError(...);
  }
  // ❌ No validation that newDueDate is in the future
  // ❌ No validation that newDueDate is valid Date object
  return new Member({
    ...this.props,
    nextDueDate: newDueDate,
    updatedAt: new Date(),
  });
}

Potential Issues:
-----------------
1. Past Date Allowed:
   const member = Member.create({status: 'active', nextDueDate: '2024-02-01'});
   const renewed = member.renew(new Date('2024-01-01'));
   ❌ Allows backwards renewal! (invalid business state)

2. Invalid Date Allowed:
   const renewed = member.renew(new Date('invalid'));
   ❌ Creates Invalid Date (corrupts database)

3. Same Date Allowed:
   const renewed = member.renew(new Date('2024-02-01'));
   ❌ No-op renewal (unnecessary database write)

Recommended Fix:
----------------
renew(newDueDate: Date): Member {
  // Existing validation
  if (this.props.status !== MemberStatus.Active) {
    throw new InvalidStatusTransitionError(
      this.props.status,
      MemberStatus.Active
    );
  }

  // NEW: Validate date is valid
  if (!(newDueDate instanceof Date) || isNaN(newDueDate.getTime())) {
    throw new ValidationError('newDueDate must be a valid Date object');
  }

  // NEW: Validate date is in the future
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  if (newDueDate <= today) {
    throw new ValidationError('newDueDate must be in the future');
  }

  // NEW: Validate date is after current due date (optional)
  if (newDueDate <= this.props.nextDueDate) {
    throw new ValidationError('newDueDate must be after current due date');
  }

  return new Member({
    ...this.props,
    nextDueDate: newDueDate,
    updatedAt: new Date(),
  });
}

Impact:
- Low risk (caller usually calculates dates correctly)
- But could cause corrupt data if bug exists in caller
- Violates domain-driven design principle (entity should validate its own invariants)

Recommendation: Add date validation to renew() method
ETA: 15 minutes

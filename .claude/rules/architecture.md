## 1. Project Initialization Protocol

### 1.1 First Command Template

Initialize a production-ready `[project-type]` following these constraints.

**Stack**

- Frontend: Next.js 14+ (App Router), TypeScript, Tailwind CSS, Shadcn UI
- Backend: Next.js API Routes / Supabase Edge Functions
- Database: PostgreSQL (via Supabase)
- Auth: Supabase Auth with RLS
- Validation: Zod schemas
- Payments: Stripe (if applicable)

**Structure** — create this exact directory layout:

```
/src
  /app              # Next.js App Router
    /(dashboard)    # Gym manager routes (standard auth)
    /(admin)        # SaaS admin routes (Supabase session + saas_admins)
      /system-health/
        page.tsx                  # System Health Dashboard
        CronStatusGrid.tsx        # Cron job monitoring component
        RawSMSFailureTable.tsx    # SMS failure tracking component
      /qr-codes/
        page.tsx                  # Gym Registration QR dashboard
        QrCodesDashboardClient.tsx # Per-gym QR: print, PNG, regenerate token
      layout.tsx                  # Admin layout: Supabase session + saas_admins check
    /api
      /members/     # Member management endpoints (JWT auth)
      /admin/       # Admin-only endpoints (Supabase session + saas_admins)
        /system-health/
          /cron-stats/route.ts    # GET cron execution logs
          /sms-failures/route.ts  # GET failed SMS with error_message
        /qr-codes/
          /route.ts               # GET all gyms' registration links
          /regenerate/route.ts    # POST rotate one gym's token (invalidates printed QRs)
        /qr-poster/route.ts       # GET a gym's 2b poster PNG (ResponseBuilder.binary)
        /system-health/access-control/route.ts  # Raw vendor errors, dead jobs,
                        # drifting clocks, near-capacity readers (rule 2.9)
      /access-control/  # Gym-facing door hardware (session + Enterprise capability
                        # via requireAccessControlGym): account, devices (+ enable/
                        # disable/unlink/open/reboot/free-space), members
                        # (sync/enrol/enrolment/biometric), events. State
                        # transitions get dedicated endpoints (rule 2.5).
      /webhooks/
        /access-control/[token]/route.ts  # Inbound device scans. Platform-wide path
                        # token is the ONLY credential (no signature scheme exists);
                        # gym resolved from device_serial, never from the body;
                        # always-200 for business outcomes.
      /cron/        # Scheduled job endpoints (CRON_SECRET auth)
  /components       # SHARED UI only (ui, common, workspace, landing, auth, legal, providers, pwa)
  /features         # Feature-first modules — ALL business logic lives here
                    #   members, payments, subscriptions, sms, auth,
                    #   announcements, registration, revenue, settings,
                    #   access-control
  /lib              # Third-party glue only (supabase, payhere, storage, cron, auth, middleware, access-control)
  /hooks            # Shared React hooks
  /utils            # Pure utility functions (api/ResponseBuilder, errors, date, phone, money)
  /types            # Shared TypeScript definitions (create only when a genuinely shared type appears)
/tests              # Integration (live-stack) and e2e tests; unit tests live in features/<domain>/tests
/docs               # product / reference / setup / ops / architecture / integrations / legal
```

There is deliberately **no top-level `/services` layer**: business logic belongs
to exactly one feature under `/features/<domain>/services`. (The former
hexagonal `src/core` + `src/infrastructure` + DI container were dissolved into
the features in the 2026-07 refactor; per-feature `services/factory.ts` modules
compose use-cases for routes and cron jobs.)

**Route Groups & Authorization**
**Route Groups & Authorization**:

- `/(dashboard)`: Standard gym manager routes with JWT session auth
- `/(admin)`: SaaS admin routes requiring a Supabase session + membership in the `saas_admins` table (via `requireSaasAdmin`/`getSaasAdmin`) — no secret is shipped to the browser. Route group, not part of the URL. (The retired `NEXT_PUBLIC_ADMIN_API_SECRET` Bearer scheme must NOT be reintroduced.)
- `/api/admin/*`: Admin-only API endpoints with strict authorization checks BEFORE database queries. **Regenerating (rotating) a gym's self-registration QR token is a SaaS-operator-only operation** — `POST /api/admin/qr-codes/regenerate` (service-role) is the _sole_ path; gym owners can VIEW their link but there is **no gym-side UPDATE policy on `gym_registration_links`**, so a gym cannot regenerate its own QR.
- `/api/public/*` + `/join/[token]`: **Public, token-authenticated self-registration** — anonymous; the unguessable per-gym token (`gym_registration_links`) is the _sole_ credential. Gym identity and the charged amount are ALWAYS resolved server-side from the token, NEVER from client input — the charged amount is the gym's active plan price plus the gym-level admission fee when `gyms.admission_fee_enabled` (both read server-side); bounded by per-IP + per-token rate limits and a honeypot. `/join/*` is whitelisted in `lib/auth-config.ts` (`PUBLIC_ROUTE_PREFIXES`); see `docs/architecture/storage-uploads.md` for the paired photo-upload flow.
- **CRITICAL RULE**: The `/system-health` frontend page and `/api/admin/system-health/*` API endpoints are strictly isolated from standard gym managers and require SaaS Admin authorization. Technical infrastructure details (error messages, stack traces, database errors) are NEVER exposed to gym managers.

## 2. Architecture Mandates

### 2.1 Twelve-Factor App Compliance

| Factor            | Implementation                           |
| ----------------- | ---------------------------------------- |
| Codebase          | Single repo tracked in Git               |
| Dependencies      | Explicitly declared in `package.json`    |
| Config            | Environment variables only               |
| Backing Services  | Treat DB/cache as attached resources     |
| Build/Release/Run | Strict separation (Vercel/Docker)        |
| Processes         | Stateless, share-nothing                 |
| Port Binding      | Self-contained (Next.js server)          |
| Concurrency       | Horizontal scaling via serverless        |
| Disposability     | Fast startup, graceful shutdown          |
| Dev/Prod Parity   | Same stack locally and in production     |
| Logs              | Stream to stdout, aggregate externally   |
| Admin Processes   | Run as one-off scripts (e.g. migrations) |

### 2.2 Type Safety Rules

Absolute requirements:
Absolute Requirements:

strict: true in tsconfig.json
Zero use of any (use unknown then narrow)
All API responses typed with Zod schemas
Database queries return typed results (Prisma/Drizzle/Supabase types)

```typescript
// ❌ NEVER
const user: any = await getUser()

// ✅ ALWAYS
const UserSchema = z.object({
  id: z.string().uuid(),
  email: z.string().email(),
  role: z.enum(['admin', 'member', 'trainer']),
})

type User = z.infer<typeof UserSchema>
const user = UserSchema.parse(await getUser())
```

Enum validation (domain enums via `z.nativeEnum()`, not duplicate `z.enum()`): see `docs/architecture/enum-validation.md`.

### 2.4 Feature-First Architecture

> **Binding growth contract.** Feature-first is the _sole_ architecture. The full,
> enforceable rulebook for how this codebase may grow — for both humans and AI agents —
> is **`docs/architecture/feature-first-growth-rules.md`**. Read it before adding,
> moving, or refactoring any code. Its rules R1/R4/R10/R11 are machine-enforced by
> `npm run arch:check` (also in the pre-commit hook) and its R1 import ban by ESLint;
> the dissolved `core/`/`infrastructure/`/`presentation/`/`services/` layers must never
> return.

Organize by domain, not by layer. Canonical feature shape (the six mandated
folders plus three optional ones):

```
/features
  /subscriptions
    /components     # UI specific to subscriptions
    /services       # Business logic: use-case classes, repositories, factory.ts
    /hooks          # State management
    /schemas        # Zod schemas
    /types          # TypeScript interfaces
    /tests          # Feature unit tests (*.test.ts, picked up by jest testMatch)
    /domain         # (optional) entities/value logic, e.g. members/domain/Member.ts
    /config         # (optional) domain constants, e.g. subscriptions/config/SubscriptionConfig.ts
    /utils          # (optional) feature-coupled helpers, e.g. members/utils/calculateNextDueDate.ts
    index.ts        # Public API
```

**Rules:**

- A feature folder should be deletable without breaking other features.
- Shared domain enums/configs (e.g. `PlanType`, `MemberStatus`) are owned by
  exactly one feature; other features import them via that feature's public
  surface, never by duplicating them.
- Route handlers contain auth + Zod validation + one service/factory call —
  **no inline Supabase queries**. Documented exceptions: per-route auth/tenant
  `gyms` lookups, `api/admin/system-health/*` infra-monitoring reads, and
  dev-only `api/demo/*`.
- Server composition goes through the feature's `services/factory.ts`
  (`create<UseCase>(supabase)`); routes pass the same client the old DI
  container used (session `createClient()` vs service-role `createAdminClient()`).
- **Shared UI is the Metric Design System** — layered L1 tokens → L2 primitives
  (`@/components/ui`) → L3 composites (`@/components/common/composites`) →
  L4 feature UI → L5 pages. Feature components compose primitives/composites and
  never fork a second implementation of a foundational pattern (Pattern Index
  §2.17; full contract in **`.claude/DESIGN_SYSTEM.md`**).

| 2.15  | Auth-boundary navigation (post-login redirect, logout) is a **full-document navigation** (`window.location.assign`/`replace`), never client-side `router.push`/`replace` — the session is mutated server-side via API-route cookies (`/api/auth/login`\|`logout`), so an SPA navigation serves the stale App Router Cache and never re-runs middleware, leaving the screen unchanged until a manual refresh. Never `router.prefetch()` a middleware-guarded route from an unauthenticated page (it caches the login redirect and poisons the destination). Sanitize the `?redirect=` param via `getSafeRedirect` (internal absolute paths only — blocks open redirects); deep-import it from `@/features/auth/utils/getSafeRedirect`, NOT the `@/features/auth` barrel, which is server-only (re-exports services that pull in `next/headers`) and cannot be imported from a client component. Mirrors the existing hard-navigation escape in `AuthRecovery`. **Password recovery is session-BEARING and `/reset-password` must never be listed in `AUTH_ROUTES`** — `/auth/callback?type=recovery` runs `verifyOtp` (writing the auth cookies) _before_ redirecting to the form, and `resetPassword()` calls `getUser()` and refuses without a session.

#### The Problem
1. **Database** has TWO date fields: `registered_date` AND `membership_start_date`
2. **Domain entity** only has ONE date field: `membershipStartDate`
3. Code tries to set `registeredDate` on domain entity, which doesn't exist

#### Resolution Options

**Option 1**: Add `registeredDate` to domain entity (RECOMMENDED)
```typescript

  membershipStartDate: Date;
  nextDueDate: Date;
  // ... rest
}
```

**Option 2**: Remove `registered_date` from database and use only `membership_start_date`
- Requires database migration
- May break existing queries
- Not recommended if `registered_date` serves different business purpose

**Option 3**: Map property names in repository layer
```typescript

  // ... other props
  membershipStartDate: dbRow.registered_date,  // Map database field to domain property
});
```

#### Recommended Approach
**Use Option 1** - Add `registeredDate` to domain entity if both dates serve different purposes:
- `registeredDate`: When member first signed up (never changes)
- `membershipStartDate`: When current membership period started (changes on renewal)

If they're the same, use **Option 2** or **Option 3**.

**Root Cause**:
Two different type definitions for SMS types:
- `ReminderSMSType`: Specific to reminder use case
- `SMSType`: Generic SMS type used by SMS provider/repository

**Analysis**:
```typescript
// ReminderSMSType likely defined as:
type ReminderSMSType = 'reminder_7day' | 'reminder_3day' | 'due_today';

// SMSType likely defined as:
type SMSType = 'welcome' | 'receipt' | 'reminder' | ...;
```

**Fix Options**:

**Option 1**: Make SMSType union include all reminder types
```typescript
type SMSType =
  | 'welcome'
  | 'receipt'
  | 'reminder_7day'   // ✅ Add specific types
  | 'reminder_3day'
  | 'due_today';
```

**Option 2**: Make ReminderSMSType a subtype of SMSType
```typescript
type SMSType = 'welcome' | 'receipt' | 'reminder_7day' | 'reminder_3day' | 'due_today';
type ReminderSMSType = Extract<SMSType, 'reminder_7day' | 'reminder_3day' | 'due_today'>;
```

**Option 3**: Type cast (not recommended)
```typescript
await smsRepo.create({
  smsType: reminderType as SMSType,  // ❌ Bypasses type safety
});
```

**Recommended**: Use **Option 1** or **Option 2** to maintain type safety.
